# Contract: E2E compose override and CI job

## `docker-compose.e2e.yml` (new, repository root, additive)

```yaml
# E2E only: raises per-IP rate limits so one browser suite (all traffic comes from the MVC container's IP) does not hit 429.
# Use: docker compose -f docker-compose.yml -f docker-compose.e2e.yml up -d --build
services:
  api:
    environment:
      RateLimiting__LoginPermitLimit: "1000"
      RateLimiting__RegisterPermitLimit: "1000"
      RateLimiting__ForgotPasswordPermitLimit: "1000"
      RateLimiting__PasswordPermitLimit: "1000"
      RateLimiting__LogoutPermitLimit: "1000"
      RateLimiting__ProfilePermitLimit: "1000"
```

No secrets, no ports, no other service touched. `docker-compose.yml` is unchanged (so `compose-smoke` keeps testing the shipped defaults). Compose merges the `environment` mapping with the base file's.

## CI job `e2e` (appended to `.github/workflows/ci.yml`; other jobs untouched)

```yaml
  e2e:
    runs-on: ubuntu-latest
    needs: docker-build
    timeout-minutes: 25
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: 10.0.x

      - name: Create throwaway .env and E2E variables (random, CI-only, never committed)
        run: |
          SA_PASSWORD="Ci-$(openssl rand -hex 12)-Aa1"
          JWT_KEY="$(openssl rand -hex 32)"
          ADMIN_USER="e2e-admin-$(openssl rand -hex 4)"
          ADMIN_PASSWORD="E2e-$(openssl rand -hex 12)-Aa1"
          echo "::add-mask::$SA_PASSWORD"
          echo "::add-mask::$JWT_KEY"
          echo "::add-mask::$ADMIN_PASSWORD"
          {
            echo "SA_PASSWORD=$SA_PASSWORD"
            echo "JWT_KEY=$JWT_KEY"
            echo "API_HOST_PORT=5028"
            echo "MVC_HOST_PORT=5256"
            echo "LOW_STOCK_THRESHOLD=5"
            echo "BOOTSTRAP_ADMIN_USERNAME=$ADMIN_USER"
            echo "BOOTSTRAP_ADMIN_PASSWORD=$ADMIN_PASSWORD"
          } > .env
          {
            echo "E2E_BASE_URL=http://localhost:5256"
            echo "E2E_ADMIN_USERNAME=$ADMIN_USER"
            echo "E2E_ADMIN_PASSWORD=$ADMIN_PASSWORD"
            echo "E2E_RESULTS_DIR=${{ github.workspace }}/test-results"
          } >> "$GITHUB_ENV"

      - name: Start the stack (with the E2E rate limit override)
        run: docker compose -f docker-compose.yml -f docker-compose.e2e.yml up -d --build

      - name: Wait for API /health      # same loop as compose-smoke
      - name: Wait for MVC home page    # same loop as compose-smoke

      - name: Build the E2E project
        run: dotnet build CategoryProduct.E2ETests -c Release

      - name: Install Playwright Chromium (browser + OS dependencies)
        run: pwsh CategoryProduct.E2ETests/bin/Release/net10.0/playwright.ps1 install --with-deps chromium

      - name: Run E2E tests
        run: dotnet test CategoryProduct.E2ETests -c Release --no-build --logger "console;verbosity=normal"

      - name: Upload failure artifacts (screenshots, traces)
        if: failure()
        uses: actions/upload-artifact@v4          # pinned: major v4 tag at implementation, exact latest v4.x.y SHA/tag recorded in Known Gaps
        with:
          name: e2e-failure-artifacts
          path: test-results/
          if-no-files-found: ignore
          retention-days: 7

      - name: Show compose state and logs on failure
        if: failure()
        run: |
          docker compose ps -a
          docker compose logs --no-color --tail=200

      - name: Tear down
        if: always()
        run: |
          docker compose -f docker-compose.yml -f docker-compose.e2e.yml down -v --remove-orphans
          rm -f .env health.json home.html
```

## Rules

- `needs: docker-build` (cheap gate); no `needs: build-test` (see research R5).
- The workflow-level env stays as is; no new secrets are defined in GitHub; every value is generated per run and masked.
- The artifact path is `test-results/` ONLY; `.env` lives at the repository root and is not matched. A task greps the YAML for `path:` lines to confirm.
- `docker compose logs` could contain bootstrap log lines: the API never logs the password (`BootstrapAdmin` logs only rule names/user names), and the password is masked anyway.
- Pinning: `actions/checkout@v4`, `actions/setup-dotnet@v4` match the existing jobs; `actions/upload-artifact@v4` uses the same major-tag style as the existing actions. If the repository later pins by SHA, this one follows. Playwright browsers match the pinned NuGet package because the script is generated by that package.
- Browser install step is before the tests and after the build (the script is a build output). `pwsh` is preinstalled on `ubuntu-latest`; if a runner image change removes it, the step fails fast with `pwsh: command not found` (documented fallback: `dotnet tool` route or `actions/setup-powershell`).
- Retries: none. A failed run is investigated from the artifact, not re-run automatically.
- Failure semantic: test failure -> job red; unreachable stack -> fixture failure (red); skipped tests would indicate a missing `E2E_BASE_URL` (a check step prints the tests' summary; T028 checks that skipped tests cannot go unnoticed).
